# 飛鏢計分相機 App

用手機鏡頭對準實體飛鏢盤，自動（或半自動）幫你計分。支援常見的飛鏢規則、
可自訂玩家人數，並可選擇「手動確認每一鏢」或「開啟自動辨識」兩種模式。

## 功能總覽

- **開鏡頭對準飛鏢盤**：即時預覽畫面上疊加飛鏢盤網格，方便對位確認。
- **相機校準**：點選飛鏢盤外緣雙倍環上的 4 個參考點（20、6、3、11 分位
  置），即可算出完整透視轉換（homography），就算手機沒有完全正對飛鏢盤
  也能校正。
- **三種常見規則**：
  - **01 倒扣**（301 / 501 / 701，可自訂開分/收尾規則：任意、雙倍、雙/三
    倍），含標準爆牌（bust）判定。
  - **Cricket 占地盤**（標準 / Cut-throat / 不計分三種計分方式）。
  - **Around the Clock**（1→20→Bull 依序過關，可選「需雙倍才算過關」進階
    模式）。
- **2-8 位玩家**，每輪 3 鏢自動輪替，也可以隨時手動按「下一位」跳過。
- **手動或自動辨識飛鏢**：
  - 手動模式：直接在相機畫面上點選飛鏢落點，或使用畫出來的飛鏢盤圖示點
    選（不需要相機也能玩）。
  - 自動模式：以影格差異（frame difference）偵測畫面中新出現且靜止不動
    的小範圍變化，視為飛鏢落點，自動計分並自動換人 —— **這是盡力而為的
    輕量視覺演算法，不是保證準確的商用電腦視覺**，請見下方「自動辨識的
    限制」。任何時候都可以復原上一鏢或手動修正。

## 專案結構

```
packages/dart_scoring_core/   純 Dart 邏輯（不依賴 Flutter，可直接用
                               `dart test` 驗證）
  lib/src/geometry/            2D 點、透視轉換（homography）數學
  lib/src/board/               標準飛鏢盤幾何 + 落點轉分數
  lib/src/game/                玩家、單次擲鏢紀錄、共用回合/悔棋邏輯
    x01/                       01 倒扣規則引擎
    cricket/                   Cricket 占地盤規則引擎
    atc/                       Around the Clock 規則引擎
  test/                        單元測試（見下方「測試」）

app/                           Flutter 手機 App（相機、UI）
  lib/state/                   GameSetup（新遊戲設定）、GameController
  lib/camera/                  相機影像處理：自動偵測、座標轉換、疊加繪圖
  lib/screens/                 首頁 / 新遊戲 / 校準 / 計分畫面
  lib/widgets/                 各模式計分板、手動點選飛鏢盤等元件
```

核心規則/幾何邏輯獨立成 `dart_scoring_core` 套件，好處是：不需要
Flutter、不需要手機或相機就能對「規則對不對」做完整單元測試，UI 與相機
層則只負責把畫面上的一個點轉成一次 `DartHit` 丟給規則引擎。

## 快速開始

Android / iOS（以及本機開發用的 Linux 桌面）原生專案資料夾已經包含在這
個 repo 裡（用 `flutter create` 產生），相機權限也已經加好，不需要再自
己跑 `flutter create`：

```bash
# 1. 安裝 Flutter（如尚未安裝）：https://docs.flutter.dev/get-started/install

cd app
flutter pub get

# 接上手機（或啟動有相機的模擬器）
flutter run
```

### 相機權限

已經加在專案裡了：

- **Android**：`app/android/app/src/main/AndroidManifest.xml` 內的
  `<uses-permission android:name="android.permission.CAMERA" />`。
- **iOS**：`app/ios/Runner/Info.plist` 內的 `NSCameraUsageDescription`。

如果之後想改權限說明文字或加其他權限，直接改這兩個檔案即可。

### 測試 / 驗證方式

```bash
# 核心規則/幾何邏輯（純 Dart，不需要裝置）
cd packages/dart_scoring_core
dart pub get && dart test          # 29 個測試

# App 層（Widget 測試 + 靜態分析）
cd app
flutter pub get
flutter analyze                    # 目前 0 warning/error
flutter test                       # 涵蓋首頁→新遊戲→（略過校準）手動計分畫面的完整流程
```

以上都已經在開發過程中實際跑過並全數通過；另外也在本機把 App 編成 Linux
桌面版本（`flutter build linux`）並用虛擬螢幕實際點擊操作過一輪 —— 開新
遊戲、進入校準畫面（沒有相機時會顯示錯誤訊息＋略過按鈕，符合預期）、略
過校準後在手動飛鏢盤上點擊 BULL / T20 / S20，分數與版面都正確更新
（501→451→391→371）並在第 3 鏢後正確自動換人。相機串流/自動辨識那部分
（`availableCameras()`、`CameraController`、`startImageStream`）因為這個
環境沒有手機或相機裝置，**還沒有在真正的相機硬體上測過**，邏輯是照
`camera` 套件的公開 API 寫的，但實機行為（尤其是不同手機的預覽旋轉/座
標系，見 `frame_geometry.dart` 的註解）還是需要你在自己的手機上跑一次
確認。

## 怎麼玩

1. 首頁 →「開始新遊戲」→ 選規則、開分/收尾方式、玩家人數與名字、是否要
   開自動辨識。
2. 校準畫面：把手機（建議用腳架固定）對準飛鏢盤，畫面上依提示依序點選
   「20 分外側雙倍環邊緣」「6 分外側」「3 分外側」「11 分外側」共 4 個
   點。完成後畫面會疊加一份依校準結果算出的飛鏢盤線框，用來肉眼確認對
   齊是否準確；覺得不準可以「重新點選」。也可以直接「略過校準，改用手
   動計分」，這樣就完全不需要相機，用畫出來的飛鏢盤點選即可。
3. 計分畫面：
   - 手動：直接在相機畫面（或手動飛鏢盤）上點一下飛鏢落點的位置。
   - 自動：開啟右上角/計分列的「自動辨識」開關後，偵測到飛鏢就會自動記
     分；每次偵測都會在畫面上標記出來，方便確認辨識是否正確。
   - 每輪 3 鏢記滿或爆牌/獲勝後自動換下一位；也可以隨時按「下一位」手
     動跳過，或「復原上一鏢」修正誤判。

## 自動辨識的限制（誠實說明）

自動偵測用的是簡單、可即時在手機上跑的「影格差異」演算法（見
`app/lib/camera/dart_landing_detector.dart`）：偵測畫面中發生變化、之後
又靜止下來的小範圍區域，當作新飛鏢落下。這不是姿態辨識或物件偵測模型，
準確度會受下列因素影響很大：

- 手機是否穩定固定（手持晃動會被誤判成變化）。
- 光線是否穩定（開關燈、影子移動都可能誤觸發）。
- 拔鏢/走近走遠的動作（已盡量用「變化範圍太大就視為人而非飛鏢」過濾，
  但仍可能誤判）。

因此**強烈建議**：自動模式搭配固定腳架、穩定燈光使用；無論開不開自動辨
識，畫面上都可以直接點擊來新增或修正一鏢，這是全程可靠的備援路徑，也是
校準完成後系統驗證是否準確對齊的方式。

另外，相機串流拿到的原始影格座標（sensor/buffer 方向）要換算成畫面上你
看到的預覽座標時，不同手機的旋轉/座標系可能有差異
（`app/lib/camera/frame_geometry.dart` 有詳細註解）；已提供標記點顯示目
前偵測結果落在畫面何處，方便在你自己的裝置上驗證與微調。

## 規則實作的慣例假設

飛鏢規則有不少地區/家規差異，以下是本專案採用的慣例（都寫在對應程式碼
的註解中）：

- **01 倒扣爆牌**：分數會變成負數、剛好變成 1（雙倍收尾時不可能靠雙倍收
  尾到 0）、或變成 0 但最後一鏢不是規定的雙倍/雙或三倍，都算爆牌；爆牌
  時整輪分數退回「這一輪開始前」的數值（業界常見做法），該輪立即結束。
- **牛眼算雙倍**：50 分（內牛眼）在雙倍收尾/開分規則中視為一次「雙倍」
  （因為牛眼即「double 25」）。
- **Cricket 記格**：牛眼外圈算 1 格、內牛眼算 2 格；某數字被某玩家「封閉
  」（3 格）後，只要還有對手沒封閉，多餘的擊中會依 Cut-throat / 標準規
  則加分或扣血；獲勝條件是封閉全部 7 個目標（20/19/18/17/16/15/Bull），
  且分數領先（標準）或落後（Cut-throat，因為此模式分數越低越好）。

## 已知限制 / 之後可以做的事

- App 邏輯與畫面已經在 Linux 桌面版本上實際編譯、執行並操作驗證過（見上
  方「測試 / 驗證方式」），但還沒有在真正的手機/相機硬體上跑過，相機旋
  轉換算等在真實裝置上可能需要微調。
- 自動辨識目前是單張影格差異的啟發式方法，之後可以換成更穩健的做法（例
  如固定機位 + 背景相減 + 更嚴謹的形狀/大小過濾，或串接一個小型物件偵測
  模型）。
- 目前假設每次只丟一支鏢進畫面；沒有處理「一次插入多支鏢造成大範圍變化
  」的情境（會被面積過濾判定為非飛鏢、需手動補登）。
- 校準/相機控制器目前每次切換畫面都會重新初始化，可以之後改成在
  `Provider` 層共用同一個 `CameraController` 以加快切換速度。
